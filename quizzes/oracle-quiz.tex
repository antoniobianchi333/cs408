\begin{questions}

\question Consider the following systems under test:

\begin{enumerate}[label=\Alph*.]
\item A sorting function on lists
\item A search engine for the library catalog, which ranks results by
  relevance
\item An image classifier that reports the number of cats in an image
\end{enumerate}

Recall that a metamorphic relation has the form
\[
  \textsf{input transformation} \;\longrightarrow\;
  \textsf{expected relation on the outputs}
\]
and that a good one is \textbf{non-trivial}, \textbf{testable},
\textbf{fault-revealing}, and \textbf{clearly scoped}.

\begin{parts}

\part For \textbf{each} of the three systems, give a metamorphic
  relation that could reveal a fault. %
  \answerspace{15} %
  \begin{solution} %
    Many correct answers. For example:

    \textbf{Sorting.} Shuffle the input $\longrightarrow$ the output is
    unchanged. Or: append one more copy of an element already in the
    list $\longrightarrow$ the output grows by exactly one element.

    \textbf{Search engine.} Add a word to the query $\longrightarrow$
    the number of results does not increase. Or: add an unrelated book
    to the catalog $\longrightarrow$ the relative order of the
    existing results is unchanged.

    \textbf{Image classifier.} Rotate or brighten the image
    $\longrightarrow$ the count is unchanged. Or: paste a second copy
    of the image beside the first $\longrightarrow$ the count doubles.
  \end{solution}
\part Give a faulty implementation of \textbf{one} of these systems
  that your relation would \emph{not} catch, and explain why it slips
  through. %
  \answerspace{11} %
  \begin{solution} %
    The point is that a metamorphic relation is a \emph{partial}
    specification --- it constrains how outputs relate, not what they
    are.

    \textbf{Sorting}, against ``shuffle $\longrightarrow$ same
    output'': a function that sorts and then removes duplicates
    survives, because shuffling the input does not change the set of
    elements. So do a function that sorts \emph{descending}, one that
    returns only the smallest element, and one that always returns the
    empty list. None of them is a correct sort, and the relation
    catches none of them.

    \textbf{Image classifier}, against ``rotate $\longrightarrow$ same
    count'': a classifier that always returns 0 satisfies it
    perfectly. This is the general trap with \emph{invariance}
    relations --- a constant function satisfies every one of them.
    Relations that pin down how the output must \emph{change} (add one
    more cat $\longrightarrow$ the count goes up by exactly one) are
    much harder to satisfy by accident.
  \end{solution}

\end{parts}
